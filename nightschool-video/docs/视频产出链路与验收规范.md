## 七、Bug 记录

### BUG-001: 配音字幕 & 跑马字幕不可见（V2-V8 均存在）

- **发现时间**: 2026-02-22
- **症状**: 视频下半部分（配音字幕 top=1378、学员标注 top=1286、跑马字幕 top=1627）全部不可见
- **根因**: `Root.tsx` Composition 尺寸定义为 `720×1280`，但所有组件坐标按 `1080×1920` 硬编码。top > 1280 的元素超出画面被裁切。
- **修复方案**: 新增严格 5.9 组合（`NightSchoolVideo59Strict`）并固定 `1080×1920`
- **修复状态**: ✅ 已修复（2026-02-22）

### BUG-002: strict59 模式下字幕显示"字幕"占位文字

- **发现时间**: 2026-02-22
- **症状**: strict59 模式使用 `StaticTemplateSubtitle` 显示静态"字幕"二字，而非动态逐字高亮
- **根因**: strict59 原设计为像素级对照模板，使用占位文字。普适化后需要真实字幕。
- **修复方案**: 统一使用动态 `CaptionPage` 逐字高亮字幕
- **修复状态**: ✅ 已修复（2026-02-22）

### BUG-003: 标题1 黄底色块撑满 93.5% 画面宽度

- **发现时间**: 2026-02-22
- **症状**: 标题1 黄底色块固定宽度 93.5%，文字短时大量留白不美观
- **修复方案**: 改为 `display: inline`，黄底宽度跟随文字长度
- **修复状态**: ✅ 已修复（2026-02-22）

## 十、素材编排规则（面向 AI 的编排决策指南）

### 核心约束

| 参数 | 值 | 说明 |
|------|---|------|
| 即梦素材物理时长 | **5.06s** | 所有即梦生成的 B-roll 素材固定时长 |
| 转场时长 | **0.8s** | fade 过渡期间两段素材重叠播放 |
| 安全余量 | **0.2s** | 避免素材末尾黑帧，实际可用 ≈ 4.86s |
| 总视频时长 | = 配音时长 | 视频时长完全由配音决定 |

### 自适应段数计算

**公式**：

```
可用单段时长 = 素材物理时长 - 安全余量 = 5.06 - 0.2 = 4.86s

n 段素材能覆盖的最长配音：
  覆盖时长 = n × 可用单段时长 - (n-1) × 转场时长
  即: T_max = n × 4.86 - (n-1) × 0.8

反推：给定配音时长 T，最少需要几段素材：
  n = ceil((T + 0.8) / (4.86 - 0.8 + 0.8))
  n = ceil((T + 0.8) / 4.86)

每段在画面中的展示时长：
  clip_sec = (T + (n-1) × 0.8) / n
```

**速查表**：

| 配音时长 T | 需要段数 n | 每段展示时长 | 是否需要调速 |
|-----------|----------|------------|------------|
| 6-7s | 2 | 3.4-3.9s | ❌ 自然裁剪 |
| 8-13s | 3 | 3.2-4.9s | ❌ 自然裁剪 |
| 14-17s | 4 | 4.1-4.85s | ❌ 自然裁剪 |
| 18-21s | 5 | 4.2-4.84s | ❌ 自然裁剪 |
| >22s | 6+ | 计算 | 可能需要减速 |

### Remotion Video 素材操控能力

AI 在编排视频时，可以使用以下 Remotion `<Video>` 组件能力来匹配素材与配音时长：

#### 1. 裁剪（Trimming）— 最常用

当素材时长 > 需要的展示时长时，自动只播放素材的一部分。

```tsx
import { Video } from "@remotion/media";

// 跳过前 0.5 秒，播放到第 4 秒
<Video
    src={staticFile("clip.mp4")}
    trimBefore={0.5 * fps}   // 起始裁剪（帧）
    trimAfter={4 * fps}      // 结束裁剪（帧）
    muted
/>
```

- **适用场景**: 素材 5.06s > 需要的 3-4s → 只播放中间最精彩的部分
- **注意**: `trimBefore` / `trimAfter` 单位是**帧**，不是秒。用 `秒 × fps` 转换。

#### 2. 加速 / 减速（Playback Rate）

当需要微调时长匹配时，可以改变播放速率。

```tsx
// 1.2 倍速播放（5s 素材在 4.17s 内播完）
<Video src={staticFile("clip.mp4")} playbackRate={1.2} muted />

// 0.9 倍速播放（5s 素材拉长到 5.56s）
<Video src={staticFile("clip.mp4")} playbackRate={0.9} muted />
```

- **安全范围**: `0.8 ≤ playbackRate ≤ 1.3`
    - < 0.8: 画面明显卡顿/慢动作
    - > 1.3: 画面明显快进，不自然
- **适用场景**: 段数已定但时长差 0.5-1s，用微调速率对齐

#### 3. 循环（Loop）

当素材太短、需要重复播放时使用。

```tsx
// 循环播放直到 Sequence 结束
<Video src={staticFile("clip.mp4")} loop muted />
```

- **适用场景**: 极端情况，配音很长且素材不足（不推荐，画面重复感强）
- **优先级最低**，应优先增加素材段数

### 编排决策树

```
给定: 配音时长 T（秒），可用素材池 M 个文件

1. 计算最少段数: n = ceil((T + 0.8) / 4.86)
2. 如果 n > M（素材不够）→ 用 loop 或减速（playbackRate=0.85）补足
3. 从素材池选取 n 段，确保课程类型不重复

4. 计算每段展示时长: clip_sec = (T + (n-1) × 0.8) / n

5. 每段素材实际播放策略:
   ├─ clip_sec < 4.86s → 自然裁剪（Sequence 限制帧数即可，最简单）
   ├─ clip_sec ≈ 4.86-5.06s → 刚好，无需处理
   ├─ clip_sec > 5.06s → 减速播放 (playbackRate = 5.06 / clip_sec)
   └─ 如果 playbackRate < 0.8 → 需要增加段数或用 loop

6. 可选优化:
   ├─ trimBefore: 跳过素材开头不精彩的部分（如前 0.3s 黑帧）
   └─ playbackRate 微调: 让相邻素材时长更均匀
```

### 课程标签与素材的匹配

```tsx
const CLIPS = ["clip-makeup.mp4", "clip-guitar.mp4", "clip-jazz.mp4"];
const CLIP_LABELS = ["美妆课", "吉他课", "爵士舞课"];

// 每段素材对应一个课程标签 Sequence
CLIP_LABELS.map((label, i) => (
    <Sequence from={clipStartFrame[i]} durationInFrames={clipFrames}>
        <CourseTag label={label} />
    </Sequence>
))
```

即梦素材文件名中通常包含课程关键词（如"美妆"、"吉他"、"爵士舞"），可据此自动匹配标签。
